# M4.5: Access control, field defaults and construction agree with C initialization

Status: **Completed** (implemented and verified in this checkout).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

Second of the hardening slices from the 2026-09-23 audit (see [M4.4](M4.4.md)
for the grouping rationale). The code is `SemaInit.cpp`, the write and
address checks in `SemaExpr.cpp`, and construction in `SemaCx.cpp`. None of
these items crashed. They were soundness holes and silently wrong values:
code that [M4c](M4c.md), [M4.1](M4.1.md), [M4e](M4e.md) and [M4f](M4f.md)
claim to reject, or to initialize, was accepted with another meaning.

Unless noted, each example starts with `#module M`. "From another module"
means a header owned by one module, included by a file owned by another.

## Access control

**1. A write or a pointer below the outermost member was not checked.** From
another module, with
```c
struct T { private struct { int hidden; }; private(set) int arr[2];
           private(set) Cell cell; private(set) Cell cells[2]; };
```
all of these were accepted:
- `t->hidden = 1`;
- `t->arr[0] = 2`;
- `int *p = t->arr`;
- `&t->cell.v`;
- `t->cells[1].bump()`, a mutating method on an element.

The write, `&` and array-decay checks now use `CheckCxWriteAccessChain`,
which walks every subobject the expression names within one object: `.`
members, elements of array members, anonymous members. It needs the write
access of each. `->` and `*` reach another object and end the chain.
- **Reads** of a member of an anonymous struct or union now need the read
  access of every field along the way. The message names the member as
  written (`'hidden'`), not the anonymous one.
- **An access specifier written before an anonymous member** used to be
  dropped, because the member has no declarator. It now applies.
- **Subscripting an array member** is checked on the element it reaches,
  like any write. Only a decay that hands out the whole array as a mutable
  pointer needs the member's write access.

**2. A `~mutating` method call on a `private(set)` member was rejected.**
`o->cell.get()`, where `get` promises not to write, failed as a write,
because the receiver's address was checked before the method was selected.
The check now runs after selection, and only for a mutating method. This bug
was found while fixing item 1; the audit had not listed it.

**3. Brace initialization was rejected when the private field has a
default.** From another module, `Guarded g = { 1 };` failed on the private
`secret = 7`, while `Guarded(shown: 1)` was accepted. A field with a default
is now written only when the list names it, positionally or by designator,
which is what the generated construction already did.

## Field defaults

**4. Defaults were dropped wherever C zero-fills.** A C record has no
constructor, so C's value-initialization is zero-filling, and that is where
every case went:
- a nested member;
- the elements an array initializer leaves out;
- the elements around a designator;
- an anonymous member;
- a member of a type with a custom `init`.

`InitListChecker::PerformEmptyInit` now initializes a record that contains
defaults at any depth, or an array of such records, from an empty list. That
gives each field its default, exactly as `T x = {};` does. A union takes its
first member that has a default. The object an `init` runs over is built the
same way.

**5. A bit-field default was warned about twice.** A construction passed the
already-converted default back through the initializer list, which converted
and diagnosed it again. The list now takes a field's own default as it is.

## Initializers and construction

**6. An `init` added in a continuation** changed construction only in the
translation unit that saw it. It is now an error: whether a type has
initializers decides how every construction of it is built, and a
continuation may be in a file other translation units never see. A
continuation can still implement an `init` the primary definition declared.

**7. Construction was refused for valid structs.** A flexible array member
was treated as a required field, and an unnamed padding bit-field disabled
construction entirely. Neither is part of the construction surface now, in
the generated one or in the object an `init` runs over.

**8. Construction at the start of a statement and inside `sizeof`.**
`P(x: 1).show();` failed with `expected ')'`, and `sizeof(P(x: 1))` with
`type-id cannot have a name`, because C commits to a declaration or a type
name there. The parser now treats two forms as a construction:
- `Type ( identifier :`: a labelled value;
- `Type ( literal`: an initializer call such as `Scale(3)`.

No declarator starts with either, so no valid C program changes meaning, as
[G01](../../OPEN-ISSUES.md#g01--c-grammar-collisions) requires. `Type(x)`,
which declares `x`, and `Type()`, a function type, keep their C meaning.

**9. `init` in a union** was accepted, though a union can never be
constructed. It is an error now.

**10. A method called on a `volatile` value** only produced C's "discards
qualifiers" warning. No method takes a volatile receiver, so it is now an
error, as a mutating call on a `const` value is.

## Permitted baseline C modes

Every C/GNU standard, as in M0. Every change is conditioned on Cx:
- **access** checks exist only for Cx access attributes;
- **default** filling applies only to records that contain a Cx default;
- **the parser rule** accepts only token sequences no C program contains.

## Tests

- **`access-chain.c`** (with `Inputs/cx-nested.h`), from another module:
  - reads through anonymous members;
  - writes to array elements, member fields and anonymous members;
  - mutating calls rejected and `~mutating` calls accepted on `private(set)`
    members;
  - pointer escapes by `&` and by array decay;
  - brace initialization naming or skipping a defaulted private field.
- **`field-defaults-nested.c`**: the value of every zero-filling case in
  emitted constants, a nested default under an `init` at `-O1`, and a single
  bit-field warning.
- **`construction-hardening.c`**:
  - flexible array member and padding bit-field;
  - construction at a statement start and in `sizeof`;
  - `Type(p)` and `Type()` keeping their C meaning;
  - `init` in a continuation and in a union;
  - a `volatile` receiver.

failed, 0 unexpected failures, with `Index/crash-recovery-modules.m` excluded

## Known limitations

- **A private or `private(set)` array member cannot decay for reading
  either.** `*t->arr` and passing `t->arr` to a function expecting `const int
  *` are rejected, because the decay hands out a mutable pointer. This is the
  same conservative rule `&` already follows ([M4c](M4c.md)); a `const`
  element type is exempt. Indexing is not affected.
- **`offsetof` of a private field is permitted.** [M4.1](M4.1.md) says
  private is compiler-enforced access, not memory protection, and C's
  `offsetof` computes a layout fact without reading or writing anything.
- **`Type(x)` at the start of a statement still declares `x`.** Construction
  with a first value that is an identifier, or with no values at all, needs
  the expression position, for example `(void)Type(x)` or `v = Type()`.
  Deciding those forms is [G01](../../OPEN-ISSUES.md#g01--c-grammar-collisions)
  work.
- **No method call on a temporary built by `init`**
  ([M4f](M4f.md)): `Scale(3).m()` is still rejected, because that
  construction is a statement expression and has no address. A generated
  construction is a compound literal, which does.
