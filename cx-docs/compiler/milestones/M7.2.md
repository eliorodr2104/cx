# M7.2: Moving resource locals

Status: **Completed** (implemented and verified in this checkout).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

A follow-up to [M7c](M7c.md), where a resource value could not leave the local
that held it.

```c
void show(const File *f)      // borrows: a pointer, as in C
void close(File f) {}         // consumes: f is destroyed here

File open(char* path) {
  File f = File(path)
  show(&f)
  return f                    // moves to the caller
}

File a = open("x.txt")
close(a)                      // a moves into close
show(&a)                      // error: 'a' is used after it is consumed
a = File("y.txt")             // a holds a value again
```

## The rule

The C spelling says who owns a resource. A pointer, `const` or not, borrows it:
nothing reached through a pointer moves. A parameter of a resource type taken by
value owns its argument. A local or a by-value parameter named directly is
*consumed* when it is passed by value, returned, or given for a field in a
construction or a braced list; on no path is it used afterwards until it is
assigned again. Swift writes the same with `borrowing` and `consuming`; Cx needs
no new words, since a resource type cannot be copied and a value parameter can
only take it.

## Semantics

- **Callee.** A by-value parameter is destroyed at the end of the function,
  unless it is consumed there in turn.
- **Paths.** A variable consumed on some paths only is destroyed at the end of
  its scope only when it still holds its value; assigning it after a consume
  destroys nothing old.
- **Not consumed:** a field, an array element, `*p`, `self`, a copy such as
  `File b = a`.
- **Loops.** A variable declared in a loop body is new each iteration; one
  declared outside and consumed inside is used after it is consumed.
- **`defer`.** A deferred block consumes nothing, and a variable a deferred
  block uses cannot be consumed.

## Representation

Sema allows the one read of a resource variable that consumes it, while it
converts a by-value argument, a returned value or a field's value, and a
flow-sensitive pass over the CFG rejects every use after a consume. A variable
consumed anywhere is marked `CxConsumed`; CodeGen gives it a flag that is set
when it gets a value and cleared when it is consumed, and destroys it at the end
of its scope only when the flag is set. A returned local placed in the return
slot by the named return value optimization clears its flag. The optimizer
removes the flag where it is constant.

## Permitted baseline C modes

Every C/GNU standard, as in M0.

## Evidence

- The full Clang lit suite passes, with the known deadlocking
  `Index/crash-recovery-modules.m` filtered out.
- The IR of `deinit-consume.c` is identical after `-E` and after `-ast-print`.
- A program that opens, borrows, returns, consumes, reassigns and moves into a
  field prints each close exactly once.

## Tests

- **`deinit-consume.c`**, as GNU17 and GNU89, then as IR, after `-E` and after
  `-ast-print`: a parameter destroyed by its callee, a returned local, a
  parameter passed on, a consume on one path, assigning after a consume, a
  generated construction and a loop.
- **`deinit-consume-errors.c`**: use after a consume, twice, on one path, in a
  loop, a deferred use, in a deferred block, and no consume through a pointer
  or a field.

## Known limitations

- **No consuming methods**: `f.close()` cannot consume `f`; a function taking
  `File` by value does.
- **`Copyable` and `~Copyable`** as spellings wait for protocols and generics
  (M8, M9).
