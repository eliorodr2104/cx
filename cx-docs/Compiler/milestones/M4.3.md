# M4.3 — Cx in code completion, and two method bugs

Status: **Completed** (implemented and verified in this checkout).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

Everything M4 added to the language was invisible to code completion, because
completion answers two questions Cx answers differently: *what are this
record's members* and *which of them may this code use*. A Cx method is not
found by C member lookup, and Cx access is not the C++ access specifier, so
the editor offered exactly the wrong set: the private fields and none of the
methods.

Probing it turned up two compiler bugs that had nothing to do with
completion, both fixed here.

## Bug 1: `~mutating int get(void)` crashed the compiler

```c
typedef struct Box { int a; ~mutating int get(void) { return a; } } Box;
```

```
Assertion failed: (NewParamInfo.size() == getNumParams() &&
                   "Parameter count mismatch!"), function setParams
```

`(void)` is an empty parameter list written the C way: the declarator carries
one unnamed void pseudo-parameter that the function type does not.
[M4a](M4a.md) built the method's parameter list straight from the declarator
and prepended the receiver, so the list had two entries against a type with
one. Any Cx method written `(void)` crashed the compiler. The pseudo-parameter
is now recognised and skipped, which is what `GetFullTypeForDeclarator` does
for an ordinary function.

## Bug 2: an unqualified name did not reach a sibling method

`language/structs.md` says an unqualified name inside a method resolves
against the receiver. It did for a field and not for another method:

```c
typedef struct S {
    int a;
    void bump(int by n) { a += n; }
    void twice(void) { bump(by: 1); }
    //                 ^ error: call to undeclared function 'bump'
} S;
```

Two things were in the way, and both are fixed.

`BuildCxImplicitSelfMemberRef` looked the method up correctly and then built
the reference through `BuildMemberReferenceExpr`, which performs ordinary
member lookup and so cannot see an associated function. It now builds the
`MemberExpr` directly, the way `self.method` does.

That alone was not enough, because a name followed by `(` never reached
`ActOnIdExpression` at all: `Sema::ClassifyName` turns `name(` into C's
implicit function declaration first. It now asks `isCxImplicitSelfMember`
before doing so and, when the name is a member of the receiver, returns
`NameClassification::Unknown()` so the expression path resolves it. A free
function called from a method is unaffected.

## Completion

### Access

A member the code being written could not use is no longer a candidate.
`ResultBuilder::isInterestingDecl` now asks `Sema::isCxMemberAccessible`,
which is `CheckCxMemberAccess` with the diagnostic taken out — the two share
one predicate, `cxMemberAccessLevelViolated`, so the two answers cannot drift
apart. The result is context-sensitive for free: a `private` field is offered
inside the type's own methods and continuations, and nowhere else.

### Methods

A Cx method is an associated function held by the record, so it lives in
`IDNS_Ordinary` while C member lookup accepts only `IDNS_Member`. That is why
[M4a](M4a.md) needed `LookupCxMethod` in the first place, and it is why the
visible-declaration walk completion uses never reached a method. The record's
methods are now offered explicitly alongside it. An initializer is not: it is
reached through `Type(...)`, never as a member.

### Signatures

```
COMPLETION: get : [#int#]get()
COMPLETION: grow : [#void#]grow(<#by: int n#>)
```

The implicit receiver is skipped, the way the C++23 explicit object parameter
already was, and a labelled parameter's placeholder carries the label the call
has to write rather than the local name.

### `self.`

`self.field` is the receiver shorthand, the one pointer that takes `.`.
Member lookup turns it into an arrow access; completion now does the same, and
offers members instead of nothing.

## Not the compiler: indentation

A closing brace one space off while typing `init(...)` in Helix is the
editor's tree-sitter C grammar, which has no rule for a member with no return
type. `clang-format` formats the same source correctly, so nothing in this
checkout produces it. A Cx grammar or a Helix language rule is the fix, and
neither lives here.

## Permitted baseline C modes

Every C/GNU standard, as in M0. The completion changes are all guarded on Cx
mode or on a Cx attribute that plain C never carries, and the `(void)` fix is
in the Cx method path only.

## Implementation

| Area | Change |
| --- | --- |
| `clang/lib/Sema/SemaCx.cpp` | the `(void)` pseudo-parameter is skipped; a sibling method reference is built directly; `getCxReceiverRecord` and `isCxImplicitSelfMember`; the access check is split into a predicate and a diagnosing wrapper |
| `clang/lib/Sema/SemaDecl.cpp` | `ClassifyName` leaves a receiver member to the expression path instead of declaring a C function |
| `clang/lib/Sema/SemaCodeComplete.cpp` | Cx access filters results; the record's Cx methods are offered; the receiver is skipped and the label shown in a signature; `self.` completes as an arrow access |

## Tests

`clang/test/Cx/code-completion.c` — from outside the type, the methods offered
with labels and without the receiver, and neither the private field nor `init`
offered; from inside, the private field offered through the `self.`
shorthand.

`clang/test/Cx/self-implicit.c` — a sibling method called unqualified and
with its label, a free function still a free function, and a local shadowing
a member.

`clang/test/Cx/struct-methods.c` gained a method written `(void)`.

Verification run on this checkout: `clang/test` 48955 passed, 30 expectedly
failed, 0 unexpected failures.

## Known limitations

- **Construction is not a completion candidate.** Typing `Box(` offers
  nothing: completion does not know that a type name followed by `(` is an
  expression in Cx, so neither the generated memberwise surface nor an `init`
  overload set is suggested. That is the remaining editor gap.
- **The index-based path is untouched.** clangd's own index can still surface
  a member from a file the current one cannot use it from; only Sema-based
  completion is filtered.
- **No signature help for construction**, for the same reason.
