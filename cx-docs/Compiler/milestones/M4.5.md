# M4.5 — Access control, field defaults and construction agree with C initialization

Status: **Planned** (audited, not implemented).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

Second of the hardening slices from the 2026-09-23 audit (see [M4.4](M4.4.md)
for the grouping rationale). This one is the `SemaInit.cpp` /
`CheckForModifiableLvalue` / construction code in `SemaCx.cpp`. These items
are soundness holes and silently wrong values, not crashes: code that M4c,
M4.1, M4e and M4f claim to reject or to initialize is accepted with the wrong
meaning.

Unless noted, each repro starts with `#module M`. "From another module" means
a header owned by one module, included by a file owned by another.

## Access control (M4c, M4.1)

1. **Writes and escapes below the outermost member are not checked.** A header
   declares:
   ```c
   struct T { private struct { int ax; }; private(set) int arr[2];
              private(set) struct { int z; } in; };
   ```
   From another module, all of these are accepted:
   - `t->ax = 1;`
   - `t->arr[0] = 2;`
   - `int *p = t->arr;`
   - `t->in.z = 3;`
   - `h->cs[0].inc()`, a mutating method on an element of a `private(set)`
     array.

   Two causes:
   - `CheckForModifiableLvalue` (`SemaExpr.cpp` ~14352) and
     `CheckAddressOfOperand` (~14992) look only at the outermost `MemberExpr`,
     and array-to-pointer decay is never checked.
   - An anonymous member reaches the field through an `IndirectFieldDecl`,
     which skips `CheckCxMemberAccess` (`SemaExprMember.cpp` ~1052, which runs
     for `FieldDecl` only).

   Fix: walk the whole lvalue chain (member, subscript, array decay) for write
   and address checks, and check every field in an indirect chain.

2. **Brace init is rejected when the private field has a default.** From
   another module:
   ```c
   typedef struct G { int shown; private int hidden = 7; } G;
   G b = { 1 };        // error: writing to private member 'hidden'
   G c = G(shown: 1);  // accepted
   ```
   `SemaInit.cpp` ~2384 checks every field, not only the ones written. Skip
   fields that are filled from their default.

## Field defaults (M4e)

3. **Defaults are dropped wherever the record is empty-initialized.** Runtime
   results from the audit:
   - `D arr[3] = {{1}}` gives `arr[2].b == 0`.
   - `{ [3] = {1} }` gives `a4[0].b == 0`.
   - `P p2 = { .z = 1 }` gives `p2.d.b == 0`.
   - With a nested member, `M m = {};` gives `m.in.q == 0`, while `In i = {};`
     gives 4.
   - A default in an anonymous struct or union gives 0.
   - Inside a type with a custom `init`, a nested `R` gets `q.r.d == 0`, and
     `R`'s own `init` then reads `d` as 0.

   An empty-initialized record becomes `ImplicitValueInitExpr`: see
   `SemaInit.cpp` ~817 and ~876, the array filler, and `SemaCx.cpp` ~999.
   Recurse into a filled `InitListExpr` whenever the record transitively has
   field defaults, for array fillers too.

## Initializers and construction (M4d, M4f)

4. **An `init` added in a continuation changes construction in its own
   translation unit only.** `W(a: 1)` calls the `init` in the implementing file
   (100) and uses memberwise construction everywhere else (1). Either reject
   `init` in a continuation, or require it in the primary definition
   (`hasCxInitializer`, `SemaCx.cpp:963`). Rejecting is the smaller rule and
   matches "declaring any custom initializer suppresses synthesis" only being
   decidable from the primary definition.

5. **Construction is refused for valid structs:**
   - a flexible array member is treated as a required field;
   - an unnamed padding bit-field disables construction entirely
     (`SemaCx.cpp` ~1126).

6. **Construction in statement position and inside `sizeof` does not parse:**
   - `P(x: 1).show();` gives "expected ')'", because it is parsed as a
     declaration.
   - `sizeof(P(x: 1))` gives "type-id cannot have a name".

   `Type ( identifier :` cannot start a valid C declarator, so treating it as
   an expression changes no C program. Check this against
   [G01](../../OPEN-ISSUES.md#g01--c-grammar-collisions) before landing, since
   M5a works in the same disambiguation code.

7. **Accepted but meaningless:** `init` inside a union, which can never be
   constructed, and `offsetof` of a `private` field from outside. Decide and
   diagnose. `offsetof` is arguably fine under "private is not memory
   protection" (M4.1); if so, say so in `access-control.md`.

8. **Small warning issues:**
   - The truncation warning for a bit-field default is printed twice.
   - Calling a method through a `volatile` receiver gives only a "discards
     qualifiers" warning.

## Tests

- **Access:** add the chain cases to `access-write.c` and `access-diags.c`,
  both from another module (`Inputs/`) and inside the owner.
- **Defaults:** add runtime-visible `-emit-llvm` checks to `field-defaults.c`
  for each initializer form in item 3, compared against the plain `= {}` value.
- **Construction:** add item 5 and item 6 to `construction.c` and
  `construction-diags.c`, and the continuation `init` to `init-diags.c`.
