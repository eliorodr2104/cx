# M4.1: Close the access and method-call holes

Status: **Completed** (implemented and verified in this checkout).

Intermediate milestone after [M4](../implementation-roadmap.md)'s four slices. It
adds no language surface; it closes four defects found by probing the M3/M4
interaction that the milestone tests did not cover.

## Why

Three of the four have one root cause: **a method's implicit receiver leaked
into places that must only see the parameters the source wrote.** M4a's tests
used methods with no argument labels, so nothing lined call arguments up with
declared parameters, and the defect stayed invisible. The fourth is an access
rule that only watched one of the ways a field can be written.

## What was wrong

### 1. Aggregate initialization bypassed access control

```c
typedef struct Guarded { int shown; private int hidden; } Guarded;

Guarded a = { 1, 2 };            // accepted
Guarded b = { .hidden = 2 };     // accepted
Guarded c = (Guarded){ 1, 2 };   // accepted
Nested  n = { { 1, 2 } };        // accepted, nested
```

[M4c](M4c.md)'s write check hangs off `CheckForModifiableLvalue` and
`CheckAddressOfOperand`, both of which see a `MemberExpr`. An `InitListExpr`
creates none, so every restriction on the type could be sidestepped with two
braces. `structs.md` says aggregate initialization keeps its C behavior, but
that is about **legacy C structs**; a Cx struct with access modifiers is not
one, and `access-control.md` says private is compiler-enforced.

The check now sits in `InitListChecker::CheckStructUnionTypes`, the single
point every record initialization reaches: aggregate, designated, compound
literal and nested alike.

### 2. Argument labels on a method call were off by one

```c
t->resize(width: 1, height: 2);   // the correct form was REJECTED
```

`CheckCxArgumentLabels` and `CxCandidateAcceptsCallLabels` compared the label
written for argument *i* against parameter *i*, but parameter 0 of a method is
`self`. The documented labelled-method form did not work at all.

### 3. A method call never resolved an overload set

`LookupCxMethod` returned the first method with that name and the call used it without
a diagnostic. Two methods that differed only in their labels were unreachable, even
though [M3c](M3c.md) defines them as valid overloads.

A method call now builds an `OverloadCandidateSet` over the record's methods
of that name and picks with `BestViableFunction`, exactly as a free function
call does; the receiver is just the first argument, which is what makes that
reuse possible. Access is checked on the method that is **selected**, not on
whichever one happened to share the name.

### 4. The receiver appeared in the mangled label section

`pick$_:value:` instead of `pick$value:`. The receiver is not a written
parameter and has no place in the label list. This changes the symbols of
labelled methods introduced in M4a; nothing outside this checkout depends on
them, and the encoding is versioned and experimental by design.

## Implementation

| Area | Change |
| --- | --- |
| `clang/lib/Sema/SemaInit.cpp` | write access checked for every field of a record being initialized |
| `clang/lib/Sema/SemaCx.cpp` | `cxSelfOffset`, used by both label checks; overload resolution in `BuildCxMethodCall`; access checked on the selected method |
| `clang/lib/Sema/SemaExprMember.cpp` | the access check moves from lookup to the call |
| `clang/lib/Sema/SemaOverload.cpp` | the candidate note skips the receiver |
| `clang/lib/AST/ItaniumMangle.cpp` | the label section skips the receiver |

## Tests

`clang/test/Cx/`:

- `access-initialization.c`: aggregate, designated, compound-literal, whole-object
  and nested initialization of a struct with a private field all rejected; a
  wholly public struct untouched; the type's own implementation still able to
  initialize it.
- `struct-methods-labels.c`: a labelled method call accepted, methods
  overloading on their labels each with their own symbol, and the wrong forms
  rejected with a note naming the expected label.

Verification run on this checkout: `clang/test` 48944 passed, 30 expectedly
failed, 0 unexpected failures.

## Known limitations

- **`private` is still reachable through raw memory**, by design:
  `access-control.md` says private is compiler-enforced access, not memory
  protection, and C casts and `memcpy` remain available.
- **Whole-object assignment is not a member write.** `*g = other;` replaces
  the object and is ordinary value semantics; `private(set)` guards the
  member, not the object. Producing the source value still needs the access
  the initialization requires.
- **No custom `init`**, so a struct with a private field remains constructible
  only from the type's own implementation. That is the missing half of
  `initializers.md`, recorded in [M4d](M4d.md).
