# M4.7 — Tooling and the preprocessor keep Cx meaning

Status: **Planned** (audited, not implemented).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

Last of the hardening slices from the 2026-09-23 audit (see [M4.4](M4.4.md)
for the grouping rationale). Nothing here touches Sema. The files are
`Frontend/PrintPreprocessedOutput.cpp`, line-marker handling in `Lex`,
`Tooling/InterpolatingCompilationDatabase.cpp`, `Index/USRGeneration.cpp`,
the AST printer and the driver's stdin path. These libraries are cheap to
rebuild on their own, so this slice can also be split across rounds without
cost.

## Preprocessed output loses ownership

1. **`-E`, `-save-temps` and `-frewrite-includes` drop `#module`.** M2 and M4.2
   record that `-E` does not round-trip, as
   [G09](../../OPEN-ISSUES.md#g09--modulebuild-contract). What they don't record
   is the consequence, and that is what makes this worth doing before G09:
   - `-save-temps` **silently changes symbols**. With
     `#module Geo\nint area(int w,int h){…}`, a plain compile emits
     `__Z13_Cx0$Geo$areaii`, but `-save-temps` emits `_area`. A multi-header
     translation unit that compiles normally fails under `-save-temps` with
     "conflicting types for 'show'".
   - `-frewrite-includes`, which crash reproducers and distributed builds use,
     moves a header's `#module` into the main file, giving "this file already
     declares a module owner".

   The minimum is to re-emit `#module X` after every line marker that enters or
   returns to an owned file, and to let a line-marker region carry an owner:
   ownership is keyed by `FileID`, which line markers do not recreate. If that
   is too close to deciding G09, the fallback is an error from `-E`,
   `-save-temps` and `-frewrite-includes` on owned input rather than a silent
   symbol change.

2. **`clangx -E -` (stdin) is preprocessed as C** (`Driver.cpp` ~3171).

## Editor and index

3. **clangd parses every Cx header as plain C** (60 errors on the audit's
   `all.h`). When clangd infers a command for a header:
   - from a `clangx` entry, it inserts `-x c-header`;
   - from a `-x cx` entry, it drops `-x` entirely.

   Add `TY_CX`/`TY_CXHeader` to `foldType`, and make `guessType` aware of the
   cx driver mode (`InterpolatingCompilationDatabase.cpp` ~104, ~236, ~251).

4. **USRs collide.** `move(x:)` and `move(y:)` are both `c:@F@move#I#`, and the
   module is not in the USR at all, so go-to-definition, find-references and
   rename conflate overloads. Add labels and owner to the USR in
   `USRGeneration.cpp`.

5. **libclang's extent for `init`** covers only the keyword, not the
   declaration.

## Dumps and printing

6. **`-ast-print` output cannot be reparsed.** It loses labels, access,
   `#module` and `~mutating`, and it prints `self` explicitly.
7. **An AST loaded with `-x ast` dumps without `cx-module`**, because
   `ASTContext::CxModules` is null on that path. The IR is still identical, so
   this is cosmetic, but it hides ownership bugs from anyone debugging with a
   dump.
