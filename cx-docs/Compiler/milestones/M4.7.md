# M4.7 — Tooling and the preprocessor keep Cx meaning

Status: **Completed** (implemented and verified in this checkout).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

Last of the hardening slices from the 2026-09-23 audit (see [M4.4](M4.4.md)
for the grouping rationale). Everything here is about what tools see of a Cx
program. The code is spread across several places:
- the preprocessor and its output;
- the driver;
- clangd's command inference;
- the index;
- the AST printer and the AST-file loader.

## Preprocessed output keeps ownership

**1. `-E`, `-save-temps` and `-frewrite-includes` dropped `#module`.**
[M2](M2.md) and [M4.2](M4.2.md) had recorded that `-E` does not round-trip.
The consequences were worse than a lost annotation:
- `-save-temps` silently changed symbols: `_area` instead of
  `__Z13_Cx0$Geo$areaii`.
- `-frewrite-includes`, which crash reproducers and distributed builds use,
  left each header's `#module` in one file, giving "this file already
  declares a module owner".

The cause is that ownership is keyed by `FileID`, while preprocessed input
holds many source files in one, told apart only by line markers. Two changes
fix it:
- **`-E` writes each file's owner** right after the marker that enters the
  file, where its `#module` was, and at the start of the primary file when
  the build assigned one with `-fcx-module=`. A new preprocessor callback,
  `CxModuleOwner`, carries it.
- **Preprocessed input takes the owner of the file each marker names.** Once
  a file has a GNU line marker (`# N "file" …`), `CxModuleOwnership` keys
  ownership by the marker's file name, and `ASTContext::getCxModuleOwner`
  looks it up through the presumed location. The file the first marker names
  is the primary file, which also takes an owner assigned by
  `-fcx-module=`.

`-frewrite-includes` needs nothing more: it copies each header's text,
`#module` included, after the header's marker. A `#line` directive does not
switch to this mode, so generated sources that use `#line` keep their
file's owner.

This settles the representation
[G09](../../OPEN-ISSUES.md#g09--modulebuild-contract) left open for
preprocessed output: ownership is written as `#module` after line markers.
It does not decide the rest of G09.

**2. `clangx -E -` preprocessed stdin as C.** The Cx driver now reads stdin
as Cx, as it reads a `.c` file.

## Editor and index

**3. clangd read Cx headers as C.** A command it infers for a file with no
compile-database entry of its own lost Cx:
- from a `clangx` entry it added `-x c-header`;
- from a `-x cx` entry it dropped `-x` altogether.

`InterpolatingCompilationDatabase` now does three things:
- it knows the Cx driver mode, where `.c` and `.h` mean Cx;
- it folds the Cx types together;
- from a `-x cx` command under any other driver, it writes `-x cx` or
  `-x cx-header` whatever the target file's extension.

**4. USRs collided.** `move(x:)` and `move(y:)` were both `c:@F@move#I#`,
and the module was nowhere in a USR. Go-to-definition, find-references and
rename therefore treated label overloads, and same-named entities of two
modules, as one symbol. A Cx entity's USR now carries its module and labels:
`c:@F@move@CX@Tools$x#I#`.

**5. libclang's extent for `init`** covered only the keyword. A method
declaration now extends to the end of its declarator, and its body extends it
further. The introducers `~mutating` and access specifiers stay outside the
extent, as C++ access specifiers do.

## Dumps and printing

**6. `-ast-print` output could not be reparsed.** Now it prints:
- argument labels before the local name, at declarations and at calls;
- access specifiers and `~mutating` on members;
- a method call on its receiver (`c->add(by: 2)`), not as a call of the
  associated function with the receiver's address;
- no implicit `self` among a method's parameters;
- the primary file's `#module`.

For a single-module file the printed source compiles to the same symbols,
and the test checks exactly that.

**7. An AST loaded with `-x ast` dumped without `cx-module`.** Only Sema
connected the preprocessor's ownership map to the `ASTContext`, and loading
an AST file has no Sema. `ASTReader::InitializeContext` now connects them.

## Permitted baseline C modes

Every C/GNU standard, as in M0. Nothing changes C:
- the `-E` directive and presumed-file ownership exist only in Cx mode;
- a C entity's USR has no Cx part;
- the printer changes apply only to Cx attributes.

## Tests

- **`preprocessed-output.c`** (with `Inputs/cx-pp-lib.h`, `cx-pp-c.h`):
  - `-E` writes the modules after the markers;
  - the `.i`, `-save-temps` and `-frewrite-includes` output each compile to
    the symbols of a direct compile, for an owned file including an owned
    and a C header;
  - a module assigned by `-fcx-module=` is written out, and the output
    compiles to the same symbols with or without the flag.
- **`driver-stdin.c`**: `__CX__` from stdin under the Cx driver, and not
  under the C one.
- **`tooling-identity.c`**: distinct USRs for two label overloads, and the
  extents of `init` and of a `~mutating` method.
- **`ast-print.c`**:
  - the printed source's Cx spellings;
  - the printed source compiles to the same symbol set as the original;
  - an AST file dumps with `cx-module`.
- **`clang/unittests/Tooling/CompilationDatabaseTest.cpp`**
  (`InterpolateTest.Cx`): commands inferred from a `clangx` entry and from a
  `-x cx` entry. This build does not build the unit-test binary
  (`LLVM_BUILD_TESTS=OFF`), so the file was compiled but not run. The same
  behaviour was checked by hand with `clangd --check` on a Cx header with
  each kind of entry: both now infer `-x cx-header`, and the header parses
  without diagnostics.

The fuzzing corpus was rerun as for the earlier slices.

Verification run on this checkout: `clang/test` 48969 passed, 30 expectedly
failed, 0 unexpected failures, with `Index/crash-recovery-modules.m` excluded
(see [M4.4](M4.4.md#build-and-test-plan)).

## Known limitations

- **`-E -P`** writes no line markers, so several files' `#module` lines land
  in one file. Compiling that output reports "this file already declares a
  module owner" rather than changing symbols.
- **Presumed-file ownership is not serialized.** A PCH built from
  preprocessed input loses its ownership. Nothing builds one today.
- **`-ast-print` of a translation unit spanning several modules** prints
  every declaration under the primary file's module. One printed file cannot
  hold several owners without line markers. A construction that runs an
  `init` still prints as the statement expression it is lowered to.
- **clangd's index** still surfaces a member from a file that cannot use it
  ([M4.3](M4.3.md)). Construction is still not a completion candidate
  either.
- **A Cx-aware demangler** is still M19.
