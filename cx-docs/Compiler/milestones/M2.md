# M2 — Module ownership and source identity skeleton

Status: **Completed** (implemented and verified in this checkout).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

This is the skeleton the roadmap asks for: the ownership model and its
validation, not the module semantics built on top of it. Nothing yet consumes
ownership — access control (M4), Cx linkage and mangling (M3), and build
artifacts (M15) are separate milestones.

## Source contract

```c
// rect.h
#ifndef RECT_H
#define RECT_H

#module Geometry

int rect_area(int w, int h);

#endif
```

```c
// app.c
#module Application
#include "rect.h"     // Geometry
#include <stdio.h>    // no owner

int app_run(void);    // Application
```

- `#module NAME` declares the module that owns the physical file it appears in.
  It is available in Cx mode only; plain C still rejects it as an invalid
  preprocessing directive.
- Ownership is per file. A file owned by one module can include a file owned by
  another, or an ordinary C header owned by nothing, and neither acquires the
  other's owner. It is not preprocessor state that leaks across an include.
- A file declares at most one owner. A second `#module` is an error whether or
  not the name matches, with a note at the first.
- The directive may sit inside a standard header guard, which is the usual
  form for a header.
- `-fcx-module=NAME` assigns an owner to the **primary** source file. It never
  reaches an included file. If that file also writes `#module`, the two must
  name the same module.
- A missing or non-identifier module name is an error; extra tokens after the
  name warn, as they do for other directives.

## Permitted baseline C modes

Every C/GNU standard, as in M0. `#module` is a Cx-mode directive and does not
depend on the selected C standard.

## Implementation

| Area | Change |
| --- | --- |
| `clang/include/clang/Basic/CxModuleOwnership.h` (new) | `FileID` → owner map, recording the name, the directive location and whether the build supplied it |
| `clang/include/clang/Lex/Preprocessor.h`, `clang/lib/Lex/PPDirectives.cpp` | `#module` dispatch and `HandleCxModuleDirective`, including the repeat and build-mismatch diagnostics |
| `clang/lib/Lex/Preprocessor.cpp` | `EnterMainSourceFile` applies `-fcx-module=` to the primary file only |
| `clang/include/clang/Basic/LangOptions.h`, `clang/include/clang/Options/Options.td` | `LangOptions::CxModuleName`, `-fcx-module=` |
| `clang/lib/Driver/ToolChains/Clang.cpp` | forwards `-fcx-module=` to `-cc1` |
| `clang/include/clang/AST/ASTContext.h`, `clang/lib/AST/ASTContext.cpp` | `getCxModuleOwner(SourceLocation)` |
| `clang/lib/Sema/Sema.cpp` | hands the preprocessor's map to the AST context |
| `clang/lib/AST/TextNodeDumper.cpp` | `-ast-dump` prints `cx-module <Name>` |

`tok::pp_module` already existed for the C++20 `module` contextual keyword. The
Cx directive is dispatched only for the `#` introducer in Cx mode, so the C++
path is untouched and `#module` remains an invalid directive everywhere else.

A declaration's owner is derived from its location rather than stored on the
declaration. Ownership is a property of a file, so a `FileID` map is the
normalized form; a per-declaration copy would be denormalized state that could
disagree with the file it came from. It also keeps `Decl` the size it was.

## AST and Sema changes

No new AST node and no Sema rule. `ASTContext::getCxModuleOwner` resolves a
location through its expansion location, so a declaration written by a macro
belongs to the file that expanded it.

## Target and runtime requirements

None.

## Tests

`clang/test/Cx/`:

- `module-ownership.c` — an owned header keeps its owner inside a differently
  owned includer; a plain C header stays unowned; declarations after the
  includes still belong to the including file's module; nothing is owned in
  plain C.
- `module-build-assignment.c` — `-fcx-module=` assigns the primary file, does
  not reach an included header, is forwarded by the driver, agrees with a
  matching `#module`, and conflicts with a different one.
- `module-diags.c` — a repeated `#module` with a note at the first; plain C
  rejects the directive.
- `module-malformed.c` — a missing module name.

Verification run on this checkout: `clang/test` 48918 passed, 30 expectedly
failed, 0 unexpected failures (48914 at M1.1 plus this milestone's four tests).

## C collisions

- `#module` was an invalid preprocessing directive in every mode, so no valid C
  program used it. The C++20 `module` contextual keyword shares `tok::pp_module`
  but is introduced differently and is unaffected.
- A macro named `module` is expanded by the preprocessor before directive
  dispatch, exactly as for any other directive name, so `#module` written by a
  macro is not silently reinterpreted.

## Known limitations

These are the parts of the module contract that [G09](../../OPEN-ISSUES.md#g09--modulebuild-contract)
gates, and are deliberately not decided here:

- ~~**Placement is not validated.**~~ Closed by [M4.2](M4.2.md): the
  directive-transparent per-file flag this asked for is recorded by the
  parser, where a header guard never arrives.
- **Conditional `#module` is not validated.** A directive inside `#if` is
  recorded as written; deterministic conditional identity is G09.
- **`-E` does not round-trip.** Preprocessed output drops `#module`, so a `.i`
  file loses its owner. The preprocessed representation is G09.
- ~~**Ownership is not serialized.**~~ Closed by [M4.2](M4.2.md), once
  [M4b](M4b.md) and [M4c](M4c.md) made continuations and `internal` access
  depend on it: the map travels in a `CX_MODULE_OWNERSHIP` record.
- **`-fcx-module=` is not recorded as PCH-relevant**, and no longer needs to
  be: since [M4.2](M4.2.md) ownership comes from the artifact, and the option
  applies only to the primary file, which a PCH never is.
- **Macro-expansion ownership is provisional.** A declaration written by a macro
  is attributed to the file that expanded it, not the file that defined the
  macro. This is the natural default, not a decision; G09 owns it.

## Runnable demonstration

```sh
clangx -Xclang -ast-dump -fsyntax-only app.c | grep cx-module
# FunctionDecl ... cx-module Geometry used rect_area 'int (int, int)'
# FunctionDecl ... cx-module Application app_run 'int (void)'
# (the declaration from the plain C header appears with no owner)
```
