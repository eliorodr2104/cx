# M1 — `var`, `let`, contextual `null`

Status: **Completed** (implemented and verified in this checkout).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

## Source contract

```c
var count = 10,
    ratio = 10.0,
    scale = 10.0f,
    limit = 10L;      // int, double, float, long — deduced independently

let pointer = &value; // int *const: the binding is const, the pointee is not
let immutable = 7;    // const int

Node *node = null;    // contextual null-pointer literal
```

- Semicolons are still required. Elision is M5.
- Each declarator in a `var` / `let` group deduces its own type. There is no
  shared inferred base type for the declaration.
- Every binding needs an initializer; `var missing;` is an error.
- `let` applies top-level `const` to the binding. A value binding becomes
  immutable; a pointer binding cannot be reassigned but its pointee can be
  mutated through it.
- Deduction preserves pointee qualification and drops top-level qualification of
  the initializer, so `var` from a `const int` yields `int`.
- Array and function decay follow the selected C dialect.
- `var`, `let` and `null` are contextual. A visible C typedef, object or macro
  with that spelling keeps its C interpretation; only a name with no visible
  ordinary-namespace declaration takes the Cx meaning.
- `null` has C23 `nullptr` semantics — type `nullptr_t`, convertible to any
  pointer type — in every supported C dialect, not only `-std=c23`.

## Permitted baseline C modes

Every C/GNU standard, as in M0. Verified against `c11`, `gnu17` and `c23`.

## Implementation

| Area | Change |
| --- | --- |
| `clang/lib/Sema/SemaCx.cpp` (new) | `Sema::isCxContextualKeyword`: ordinary-namespace lookup decides whether a Cx contextual spelling is available |
| `clang/lib/Parse/ParseDecl.cpp` | `Parser::isCxInferenceSpecifier`; `var` / `let` in `ParseDeclarationSpecifiers` and `isDeclarationSpecifier` |
| `clang/include/clang/Sema/DeclSpec.h` | `DeclSpec::CxInferred` marks a specifier written as `var` / `let` |
| `clang/lib/Sema/SemaDecl.cpp` | `BuildDeclaratorGroup` takes `AllowIndependentDeduction`, set from the DeclSpec |
| `clang/lib/Sema/SemaExpr.cpp` | contextual `null` on an empty lookup; C23 nullptr conversions enabled for Cx |
| `clang/include/clang/Basic/LangOptions.h` | `LangOptions::hasCNullPtrType()` |
| `clang/lib/AST/TypePrinter.cpp`, `clang/include/clang/AST/PrettyPrinter.h` | print a deduced placeholder as `var` in Cx mode |

`var` and `let` reuse the existing `__auto_type` deduction machinery
(`DeclSpec::TST_auto_type`), which already deduces per declarator and accepts a
`const` type qualifier. No new AST node, no new `AutoTypeKeyword`, and no change
to C `auto` in any C dialect. `null` reuses `Sema::ActOnCXXNullPtrLiteral`, so it
produces the same AST and lowering as C23 `nullptr`.

## AST and Sema changes

None beyond the option and group-deduction plumbing above. A `var` binding is an
ordinary `VarDecl` whose type contains an `AutoType` with the GNU keyword; `null`
is a `CXXNullPtrLiteralExpr` of type `nullptr_t`.

## Target and runtime requirements

None.

## C collisions

- `var` / `let` as a typedef or object name, and `null` as a macro or object
  name, are the collisions this milestone resolves. Resolution is by visibility:
  the C declaration always wins. Covered by the two `*-c-compat.c` tests.
- Macros never reach the contextual check because the preprocessor expands them
  first, which is the behavior the compatibility contract requires.

## Known limitations

- `var text = "hello";` deduces `char *`, following the selected C dialect. The
  Cx text default is G10 and is not decided here.
- `var p = null;` deduces `nullptr_t`, not a pointer type. This follows C23
  `auto p = nullptr;` and is not a separate Cx rule.
- A deduced placeholder prints as `var` in every Cx diagnostic, including for a
  declaration literally written `__auto_type`. Plain C is unaffected. There is
  no separate `let` spelling in diagnostics; a `let` binding reports its
  deduced type as `const var`.
- `let` does not yet exist as a stored-field declaration; fields are M4.
- No `nil`, no `Optional<T>`, no `T?` — those are M10 under G03.

## Runnable demonstration

```c
int value = 41;
int main(void) {
  let p = &value;
  *p = *p + 1;          // the pointee is mutable
  var total = 0, half = 0.5;
  total = *p;
  int *n = null;
  return (n == null && total == 42) ? 0 : 1;
}
```

```sh
clangx -std=c11 demo.c -o demo && ./demo; echo $status   # 0
```
