# M4.2: Close the M2–M4 leftovers

Status: **Completed** (implemented and verified in this checkout).

Baseline: the pinned checkout recorded in the [M0 record](M0.md).

Every M0–M4 record carries a *Known limitations* section. Most of those items
belong to a later milestone by construction, or to an open issue that has to
be settled first. Five did not: they were things the milestone that recorded
them could have done, and two of them had grown teeth as later slices built on
top of them. This milestone closes all five.

## 1. A near miss in a continuation is reported

Recorded by [M3c](M3c.md) and [M4b](M4b.md), owned by
[G04](../../OPEN-ISSUES.md#g04--source-model-and-visibility).

```c
struct T { void set(int value x); };        // declared
struct T { void set(int val x) { ... } };   // label drifted
```

Before, this compiled silently: the continuation introduced a *second* member
and the declared one was left without an implementation, so the only signal
was `Undefined symbols: T::_Cx0$D$set$value:(T*, int)` from the linker. A
one-character difference in a label produced a link error and no diagnostic.

Now a continuation member that matches a declared, still-unimplemented member
by name and by number of written arguments, yet is not a redeclaration of it,
is reported where it is written. It is an error by default, in the group
`-Wcx-near-miss`, because the alternative reading is legal but rare. It would be a
deliberate overload that differs only in labels and is introduced in a continuation
while the same-named member is defined in another translation unit.
`-Wno-cx-near-miss` allows it.

The check runs only in a continuation. Inside the primary definition, two
same-named members are an ordinary overload pair.

What still needs M15 is the other half: nothing reports a declared member that
acquired *no* definition anywhere. That needs the module-wide view, because a
translation unit that merely includes the header is not supposed to implement
anything.

## 2. Module ownership travels with a PCH

Recorded by [M2](M2.md), owned by
[G09](../../OPEN-ISSUES.md#g09--module-build-contract).

Ownership is a `FileID → Owner` map, deliberately not a per-declaration field,
so it could not disagree with the file it came from. It was also not
serialized, which was invisible in M2 because nothing consumed ownership yet.
[M4b](M4b.md) and [M4c](M4c.md) then made continuations and `internal` access
depend on it, and the gap became reachable:

```sh
clangx -x cx-header -o c1.pch c1.h
clangx -include-pch c1.pch -fsyntax-only c1.c   # error: redefinition of 'Counter'
```

The same source through `#include` was accepted. The map is now written as a
`CX_MODULE_OWNERSHIP` record with one entry per owned file. Each entry records the
file, module, `#module` location, and whether the build assigned it. The reader loads
the data into the preprocessor's map through the ordinary source
location remapping.

`-fcx-module=` is still not compared by the AST reader's language-option
check, and no longer needs to be: ownership now comes from the artifact, and
the option applies only to the primary file, which a PCH never is.

## 3. Module-owned data carries its module

Recorded by [M3a](M3a.md).

```c
#module Shapes
int counter = 0;        // @"_Z19_Cx0$Shapes$counter"
static int local = 1;   // @local
```

Only functions had Cx linkage, so an owned file's globals kept plain C
symbols and two modules with a global of the same name collided. An
externally visible file-scope variable in an owned file now carries the
module in its symbol, decided by its first declaration exactly as a
function's is: data first declared in an unowned C header is a C entity and
stays one when an owned file defines it. Internal linkage is already distinct
from every other translation unit, so a `static` keeps its plain name.

`mangleCxName` took a `FunctionDecl`; it takes a `NamedDecl` now and writes
the label section only when there are parameters to write it from.

## 4. A Cx message for a write through a `~mutating` receiver

Recorded by [M4a](M4a.md).

```
error: cannot modify 'a' through the receiver of '~mutating' method 'bad'
note: remove '~mutating' from 'bad' if it modifies the receiver
```

Before, this was C's generic *"cannot assign to variable 'self' with
const-qualified type 'const struct S *'"*, which describes the mechanism and
not the promise. The new message fires for assignment, compound assignment,
increment and address-taking alike, through member access, indexing and
dereference, and only when the enclosing method really is `~mutating`. A write
that reaches no member, such as `*self = other`, keeps C's own diagnostic.

## 5. `#module` must precede the file's declarations

Recorded by [M2](M2.md), owned by
[G09](../../OPEN-ISSUES.md#g09--module-build-contract).

M2 recorded why the check was not shipped: the preprocessor's "any tokens read
before this directive" flag is also set by a header guard's `#ifndef` /
`#define`, and `source-model.md` shows `#module` *inside* a guard. Rejecting
the documented form would have been worse than not checking.

The directive-transparent per-file flag required by M2 is now recorded by the
**parser** at the start of every external declaration.
Directives never reach the parser, so a header guard is transparent by
construction, and Clang's single-pass lexing means the flag is already set by
the time a later `#module` is handled.

```c
int before;     // note: first declaration in this file is here
#module Late    // error: '#module' must precede every declaration in its file
```

A `#module` directive inside `#if` is still not validated.
That is deterministic conditional identity, which is G09's to decide and not a
missing check.

## Permitted baseline C modes

Every C/GNU standard, as in M0. Nothing here changes plain C: the near-miss
check, the placement check and the `~mutating` message only exist for Cx
constructs, and variable mangling follows `CxLinkageAttr`, which plain C never
carries.

## Tests

- `clang/test/Cx/near-miss.c`: a drifted label and a drifted parameter type
  both reported; an exact match silent; a member introduced only in the
  continuation silent; `-Wno-cx-near-miss` accepting the file.
- `clang/test/Cx/module-ownership-pch.c`: a continuation of a type read from
  a PCH, checked to produce the same symbols as the same source through
  `#include`.
- `clang/test/Cx/linkage-variables.c`: an owned global mangled, a `static`
  not, and a global first declared in an unowned header keeping its C symbol.
- `clang/test/Cx/struct-methods-mutating-diags.c`: the new message for a
  field, an array element and `self.field`; a mutating method unaffected; a
  local unaffected.
- `clang/test/Cx/module-placement.c` and `module-placement-guard.c`: the
  placement error, and `#module` inside a header guard still accepted.

`clang/test/Cx/struct-methods-mutating.c` and `compound-references.c` were
updated: the first asserted the message point 4 replaced, the second the
unmangled symbols of module-owned data.

Verification run on this checkout: `clang/test` 48953 passed, 30 expectedly
failed, 0 unexpected failures.

## Known limitations

- **A declared member that is never implemented anywhere is still not
  reported.** M15.
- **Conditional `#module` is not validated.** G09.
- ~~**`-E` still does not round-trip `#module`.**~~ Closed by
  [M4.7](M4.7.md).
- **Macro-expansion ownership** is still attributed to the expanding file.
  G09.
- **The near-miss check is per translation unit**, like everything else about
  the overload set, so a declaration and a definition that never meet in one
  translation unit cannot be compared. M15.

